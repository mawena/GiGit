# GiGit v0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** First usable release of GiGit: a native Rust desktop git client with a persistent repo sidebar, commit graph, real-index staging (file / hunk / line), commit + amend, discard, fetch / pull / push, FR/EN UI, switchable themes, settings, and a `.deb` package.

**Architecture:** One crate `gigit` with a library (`src/lib.rs`, all logic, unit-tested) and a thin binary (`src/main.rs`). Git is driven through the `git` CLI (`std::process::Command`) and its machine-readable output is parsed into plain structs. The egui UI never blocks: each open repo has a worker thread that runs git jobs serially and sends results back over a channel, followed by `ctx.request_repaint()`.

**Tech Stack:** Rust 1.99 stable, `eframe`/`egui` (latest at `cargo add` time), `notify` + `notify-debouncer-mini`, `rfd`, `serde` + `toml`, `directories`, `thiserror`, `anyhow` (binary only), `sys-locale`, `dark-light`; dev: `tempfile`. Packaging: `cargo-deb`.

**Spec:** `docs/superpowers/specs/2026-10-26-gigit-design.md`

**Scope of this plan:** spec §5.1, §5.2, §5.3 (except image diff and `.gitignore` editor), §5.6 (fetch / pull / push / force push only), §5.9, §6, §7, §8, §8bis (except askpass and auto-stash dialog). Out of scope here, planned for v0.2.0: branches/tags/checkout/reset/drag-drop/merge/rebase/squash/cherry-pick/revert/conflicts/auto-stash dialog. For v0.3.0: stash, submodules, remotes management, clone, `.gitignore` editor, image diff, askpass bridge, keyboard shortcuts.

## Global Constraints

- Linux only (X11 and Wayland); do nothing that prevents a later port.
- Minimum git: 2.43. Do not use newer git flags.
- Every git invocation goes through `git::run` (Task 1). Never link libgit2.
- Until the askpass bridge (v0.3), **every** git command runs with `GIT_TERMINAL_PROMPT=0`, stdin null (unless data is piped), and is detached from any controlling terminal (`setsid` in `pre_exec`, `libc` crate), so a credential prompt fails fast instead of hanging a worker. Read-only commands also set `GIT_OPTIONAL_LOCKS=0`. `RunOpts.background` stays in the API (v0.3 will use it to enable askpass only for user-initiated commands).
- Never block the UI thread on git, disk scans or network.
- At most one git write operation at a time per repo (guaranteed by the per-repo worker, Task 11).
- Removing a repo from the sidebar never touches the disk.
- Destructive actions always ask for confirmation: discard, force push (and, from v0.2, reset hard and branch deletion).
- Git errors are shown in clear: a readable message, plus the full command and stderr in a collapsible section.
- No hard-coded UI string: every label goes through `i18n::tr` (Task 9). Raw git output is shown untranslated.
- Theme tokens only: no literal colour in UI code outside `src/theme.rs`.
- Config file: `~/.config/gigit/config.toml` (via `directories::ProjectDirs::from("", "", "gigit")`).
- Default theme "Sombre chaleureux" palette, exactly: bg `#1e1e2e`, sidebar `#181825`, panel `#24273a`, border `#313244`, selection `#313244`, text `#cdd6f4`, muted `#9399b2`, accent `#f5a97f`, lanes `#f5a97f #cba6f7 #a6e3a1 #89b4fa #f9e2af #f5c2e7 #89dceb #fab387`.
- Git flow: work on `feature/<name>` off `develop` (`git flow feature start <name>` / `git flow feature finish <name>`), release with `git flow release start 0.1.0` / `finish`, tag prefix `v`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Each task ends with `cargo test` green and `cargo clippy --all-targets -- -D warnings` clean.

## Review Focus

- **Brand-new repo with no commits** (`git init` then nothing): the graph must show an empty state and allow the first commit, with no "does not have any commits yet" error banner. Test in Task 3 (`log_on_empty_repo_is_empty`) and Task 6 (`first_commit_on_empty_repo`).
- **Paths with spaces, accents, quotes or a newline**: status, staging and diff must handle them, so `-z` everywhere and paths passed after `--`. Tests in Task 2 (`parses_paths_with_spaces_and_unicode`) and Task 6 (`stage_path_with_spaces`).
- **Detached HEAD or a branch without upstream**: the toolbar shows no ahead/behind, and Push on a branch with no upstream runs `push -u origin <branch>`. Tests in Task 2 (`parses_detached_head`, `parses_branch_without_upstream`) and Task 6 (`push_without_upstream_sets_it`).
- **Large repo (≥ 10 000 commits)**: the log loads in pages of 500, and scrolling to the bottom loads the next page. Test in Task 3 (`log_pagination_skip_limit`); the layout cost is covered by Task 7 (`layout_10k_linear_under_50ms`).
- **Sidebar folder deleted, moved, or not a git repo**: the entry is greyed, can still be removed, and the app does not crash. Tests in Task 8 (`probe_missing_dir`, `probe_not_a_repo`).

### Task 5: Partial patch builder (hunk / line staging)

**Files:** Create `src/git/patch.rs`

**Interfaces:**
- Consumes: `FileDiff`, `Hunk`, `DiffLine`
- Produces:
  - `pub type LineSel = std::collections::HashSet<(usize /*hunk*/, usize /*line*/)>;`
  - `pub enum PatchMode { Forward, Reverse }`
  - `pub fn build_patch(file: &FileDiff, sel: &LineSel, mode: PatchMode) -> Option<String>` — `None` if no selected Added/Removed line
  - Forward is used to **stage** lines from an unstaged diff (`apply --cached`). Reverse is used to **unstage** from a staged diff (`apply --cached --reverse`) and to **discard** from an unstaged diff (`apply --reverse`).

Algorithm (Selected Context lines are ignored):
```
for each hunk h with ≥1 selected change line:
  out = []
  for each line l (index i):
    selected = sel.contains((h,i))
    match (l.kind, mode, selected):
      (Context,_,_)                  → keep as ' '
      (Added,  _, true) | (Removed, _, true) → keep with its sign
      (Added,  Forward, false)       → drop
      (Removed,Forward, false)       → emit as ' ' (context)
      (Added,  Reverse, false)       → emit as ' ' (context)
      (Removed,Reverse, false)       → drop
    "\ No newline at end of file" follows an emitted line iff l.no_newline;
    if a dropped line had no_newline, and the previous emitted line is
    context sourced from the same side, move the marker onto it.
  old_len = count(' ') + count('-'); new_len = count(' ') + count('+')
  old_start = h.old_start; new_start = old_start + running_offset
  running_offset += new_len - old_len
  emit "@@ -old_start,old_len +new_start,new_len @@\n" + out
patch = file.header joined + hunks; apply with `git apply --cached [--reverse] --recount -`
```

- [ ] **Step 1: Write failing tests** (pure, on parsed FileDiffs built from literal diff text):
  - `whole_hunk_selection_reproduces_hunk`: selecting every change line of a 1-hunk diff → patch body equals original hunk body.
  - `forward_unselected_removed_becomes_context`: `-a\n+b` select only `+b` → body ` a\n+b`, header `@@ -1,1 +1,2 @@`.
  - `reverse_unselected_added_becomes_context`: same diff, Reverse, select only `-a` → body `-a\n b`, header `@@ -1,2 +1,1 @@`.

### Task 7: Graph lane layout

**Files:** Create `src/graph.rs`

**Interfaces:**
- Consumes: `Commit`
- Produces:
  - `pub struct Edge { pub from_lane: usize, pub to_lane: usize, pub color: usize }` — drawn from this row's centre to the next row's centre
  - `pub struct Row { pub lane: usize, pub color: usize, pub edges: Vec<Edge> }`
  - `pub struct Layout { pub rows: Vec<Row>, pub max_lanes: usize }`
  - `pub fn layout(commits: &[Commit]) -> Layout` (input in `--date-order`, children before parents)

Algorithm:
```
lanes: Vec<Option<(id, color)>> ; next_color = 0
for (r, c) in commits:
  targets = indices j with lanes[j].id == c.id
  lane = targets.first() or first None slot or push new slot (new color = next_color++)
  color = lanes[lane].color if targeted else the new color
  if r > 0: in rows[r-1].edges, every edge whose to_lane ∈ targets gets to_lane = lane
  for j in targets, j != lane: lanes[j] = None          // branches converge here
  lanes[lane] = c.parents.get(0).map(|p| (p, color))     // None ends the lane (root)
  edges = []
  for p in c.parents[1..]:
     if some k has lanes[k].id == p: edges.push(lane→k, lanes[k].color)
     else k = first None or push; lanes[k] = (p, next_color++); edges.push(lane→k, that color)
  if lanes[lane].is_some(): edges.push(lane→lane, color)
  for every other j with lanes[j].is_some() and not set in this row: edges.push(j→j, lanes[j].color)
  trim trailing None slots; max_lanes = max(max_lanes, lanes.len(), lane+1)
  rows.push(Row{lane, color, edges})
```
